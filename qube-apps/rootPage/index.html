01 — About

Containers without hiding the machine.

Qube is intentionally small and direct. It gives you a Docker like workflow while keeping the interesting parts visible: root filesystems, namespace setup, process tracking, cgroup controls, image extraction, and lifecycle commands.

Built withGo

02 — Features

Small surface area, real runtime pieces.

Qube focuses on the core path: pull an image, create a filesystem, launch a process in isolated namespaces, track it, inspect it, and tear it down cleanly.

01

Namespace isolation

PID, mount, IPC, UTS, and optional network isolation for containerized workloads.

02

cgroups v2

Resource-control hooks for CPU and memory so containers are observable and bounded.

03

Image workflow

Pull images from Qube Hub, extract root filesystems, and reuse them across runs.

04

Control plane

CLI, daemon, REST API, and WebSocket execution paths for local and programmatic control.

03 — Quickstart

Build it, pull an image, run a workload.

Qube is Linux-only because it depends on kernel features. From Windows, build and run it inside WSL or deploy it to a Linux host.

git clone https://github.com/Voyrox/Qube && cd Qube && make build
STEP 01

Build the Linux binary

Compile Qube for the runtime host.

make build
STEP 02

Pull an image

Download a root filesystem from Qube Hub.

sudo qube pull Voyrox:nodejs:25.2.0
STEP 03

Start the container

Run your command with ports, env vars, and volumes.

sudo qube run --image Voyrox:nodejs:25.2.0 --ports 3000 --cmd "npm start"
